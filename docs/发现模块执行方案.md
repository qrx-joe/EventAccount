# 发现模块（用户端首页内容）执行方案 V2

## 1. 背景与目标

在已完成 V1（发现首页四区块 + 活动详情补齐 + 社区详情 V1）的基础上，对齐 Luma 的发现页核心体验，重点补齐“可探索深度”和“可持续浏览能力”。

本次 V2 聚焦三件事：

- 发现页从静态展示升级为可筛选、可排序、可分页的探索入口。
- 建立 View All 深链（分类流、日历/社区流），避免内容被首屏截断。
- 补齐搜索闭环（活动 + 社区），并预留搜索历史能力。

---

## 2. 现状评估（对照 Luma）

### 2.1 当前已具备

- 发现页四区块：`frontend/src/views/discover/DiscoverView.vue`
  - 热门活动
  - 按类别浏览
  - 精选社区（Category 映射）
  - 探索本地活动
- 活动详情页：`frontend/src/views/event/EventDetailView.vue`
  - 报名状态
  - 相关推荐
- 社区详情页：`frontend/src/views/community/CommunityDetailView.vue`
  - 订阅/取消订阅
  - 列表/日历/地点聚合（V1）

### 2.2 与 Luma 仍有差距

- 缺少城市/区域发现入口（Luma 的 Explore Local Events 结构）。
- 分类和社区缺少 View All 深链，首屏之外内容不可持续浏览。
- 热门活动当前接近静态截断，不是“热门排序策略”。
- 查询维度不足（地点、日期、排序）导致探索粒度不够。
- `/calendars` 仍为占位指向 `DiscoverView`，语义与导航不一致。
- 搜索历史未落地。

---

## 3. V2 设计原则

- **最简可落地**：先补查询能力和深链，再做体验增强。
- **前后端一致**：筛选参数前后端同名、同语义，避免二次映射。
- **逐步替换**：保留 Category -> Community 过渡方案，不做向后兼容层。
- **先验证再扩展**：每个阶段必须通过类型检查与关键路径回归。

---

## 4. 实施计划（V2）

## Stage 1：发现筛选能力补齐（P0）

**目标**：把发现页从“展示页”升级为“可探索页”。

**范围**：

- 后端事件查询扩展参数：
  - `city`
  - `dateStart`
  - `dateEnd`
  - `locationType`
  - `sortBy`（`latest` / `trending` / `upcoming`）
- 前端发现页新增筛选控件并透传参数。
- 保留现有关键词与分类筛选，形成组合查询。

**涉及文件**：

- `backend/src/modules/event/event.dto.ts`
- `backend/src/modules/event/event.service.ts`
- `backend/src/modules/event/event.controller.ts`
- `frontend/src/types/index.ts`
- `frontend/src/lib/events.ts`
- `frontend/src/views/discover/DiscoverView.vue`

**验收标准**：

- 筛选参数可组合生效（关键词 + 分类 + 时间 + 地点 + 排序）。
- 空态/加载态/错误态保持可用。
- 类型检查通过。

---

## Stage 2：热门活动排序策略（P0）

**目标**：把“热门活动”从静态截断改为策略排序。

**范围**：

- 后端增加 `sortBy=trending` 逻辑（优先使用可用热度信号：报名量、门票售卖、时间衰减）。
- 前端热门区块改为调用 `trending`，移除本地 `slice` 充当热门逻辑。

**涉及文件**：

- `backend/src/modules/event/event.service.ts`
- `frontend/src/views/discover/DiscoverView.vue`

**验收标准**：

- 热门列表与最新列表结果明显不同。
- 同一数据集下排序结果稳定可复现。

---

## Stage 3：城市探索区块（P1）

**目标**：补齐 Luma 式“按城市发现活动”入口。

**范围**：

- 发现页新增区域 Tabs（如亚太、北美、欧洲）与城市卡片。
- 展示城市活动数，点击城市联动事件流过滤。
- V2 最简实现优先复用现有数据聚合；后续可替换为后端城市聚合接口。

**涉及文件**：

- `frontend/src/views/discover/DiscoverView.vue`
- `frontend/src/views/discover/components/CityExplorer.vue`（新增，可选）

**验收标准**：

- 区域切换正常。
- 城市点击可驱动事件列表变化。
- 移动端布局正常。

---

## Stage 4：View All 深链页（P1）

**目标**：补齐“查看更多”路径，提升持续浏览能力。

**范围**：

- 新增分类发现落地页：`/discover/category/:slug`
- 新增日历/社区流落地页：`/discover/calendars`
- 修正顶部导航 `/calendars` 路由，移除占位复用。

**涉及文件**：

- `frontend/src/router/index.ts`
- `frontend/src/components/layout/TopNavBar.vue`
- `frontend/src/views/discover/CategoryDiscoverView.vue`（新增）
- `frontend/src/views/discover/CalendarsDiscoverView.vue`（新增）

**验收标准**：

- 发现页关键区块都存在 View All 跳转。
- URL 可直接访问与分享。
- 页面支持分页/继续浏览。

---

## Stage 5：搜索闭环（P1）

**目标**：把发现页搜索升级为“活动 + 社区”的统一入口。

**范围**：

- 活动搜索沿用 `GET /events`。
- 社区搜索在 V2 使用 Category 映射查询。
- 同一输入返回活动结果与社区结果。

**涉及文件**：

- `frontend/src/views/discover/DiscoverView.vue`
- `frontend/src/lib/categories.ts`
- （必要时）后端 category 查询 DTO / service

**验收标准**：

- 支持活动/社区双结果展示。
- 无结果态文案明确，且可一键清空筛选。

---

## Stage 6：搜索历史与质量门禁（P2）

**目标**：完善使用闭环并建立回归保障。

**范围**：

- 搜索历史（V2 推荐先做本地版 `localStorage`）：
  - 最近搜索展示
  - 点击回填
  - 删除单项 / 清空历史
- 增加关键路径测试：
  - 前端 Playwright：筛选、跳转、View All、订阅
  - 后端接口测试：组合参数、排序、分页

**涉及文件**：

- `frontend/src/views/discover/DiscoverView.vue`
- `frontend/src/lib/*`（按实现拆分）
- `frontend/tests/*`（新增）
- `backend/test/*`（新增）

**验收标准**：

- 发现模块主链路自动化测试通过。
- 搜索历史交互稳定且不影响现有查询。

---

## 5. 里程碑

- **M1（P0）**：筛选能力 + 热门策略完成（Stage 1-2）。
- **M2（P1）**：View All 深链 + 城市探索完成（Stage 3-4）。
- **M3（P1/P2）**：搜索闭环 + 搜索历史 + 自动化测试完成（Stage 5-6）。

---

## 6. 风险与处理

- **Category 与 Community 语义错位**：V2 继续采用映射，后续引入真实 community 模块时做替换迁移。
- **热门排序数据不足**：先用可获取指标，保留策略升级点，不阻塞主链路上线。
- **城市字段一致性不足**：V2 允许前端聚合作为过渡，后续补后端标准化城市维度。

---
