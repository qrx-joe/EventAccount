# 个人职责说明

> 本文档说明我在 EventAccount（T3 Program）项目中端到端独立负责的三大模块。

## 项目背景

EventAccount 是仿照 [Luma](https://lu.ma) 的线上活动报名与管理平台，覆盖活动创建、报名、签到、社区运营全流程。前端基于 Vue 3 + TypeScript + Tailwind CSS v4 + shadcn-vue，后端基于 NestJS + TypeORM + PostgreSQL + Redis。

---

## 我负责的模块

### 一、个人中心模块（账号设置）

用户登录后的自管理入口，前端路由 `/settings/*`，后端路由 `/users/me/*` + `/users/:id`。

#### 前端职责

- **SettingsLayout.vue**：左导航 + 右内容的两栏壳布局
- **ProfileSection.vue**：个人资料编辑（头像 / 昵称 / 个性签名），头像 URL 防抖 600ms 校验 + `<img>` 实时预览
- **SecuritySection.vue** + 4 个 Dialog 组件：
  - `ChangePasswordDialog`：修改密码（@Match DTO 校验，前端 zod 实时反馈）
  - `ChangePhoneDialog`：换绑手机号（短信验证码 + 60s 倒计时）
  - `ChangeEmailDialog`：换绑邮箱（邮箱验证码 + 60s 倒计时）
  - `DeleteAccountDialog`：注销账号（需手动输入"删除账号"确认文本）
- **AppearanceSection.vue**：亮色 / 暗色 / 跟随系统三档主题切换
- 抽离 `useTheme` / `useCountdown` / `useSmsCountdown` / `useEmailCountdown` 四个 Composable 复用倒计时与主题逻辑
- 头像上传：基于 shadcn-vue 自定义 Avatar + 文件类型 / 大小前置校验

#### 后端职责

- **Controller 拆分**：
  - `UserController` 走 `/users/:id`，`ParseUUIDPipe` + 本人校验
  - `UserAccountController` 走 `/users/me`，JWT payload 直接定位用户，不接受 URL 参数
- **Service 拆分**：`UserService`（基础 CRUD）与 `UserSecurityService`（安全变更），职责分离
- **事务化安全变更**：换绑手机 / 邮箱采用 Redis 验证码消耗 → DB 事务内冲突检查 + 写入，消除 TOCTOU 竞态
- **唯一约束兜底**：统一捕获 PG `23505` 错误码转 409
- **限流**：`@Throttle(5, 60)` 装饰修改密码 / 换绑手机 / 换绑邮箱接口
- **Entity 层双重保护**：`password` 字段 `select: false` + `toSelfDto()` 显式映射
- **上传服务魔数校验**：基于 `IMAGE_SIGNATURES` 做文件真实类型校验，不信任客户端 mimetype

### 二、落地页（Landing Page）

未登录访客入口，首页 / About / Features / Help / Terms / Privacy 共 6 个页面。

#### 前端职责

- **页面容器**：`LandingView` / `AboutView` / `FeaturesView` / `HelpView` / `AgreementView`
- **组合子组件**：`LandingNav` / `LandingHero` / `LandingFeatures` / `LandingCta` / `LandingFooter`
- **认证状态感知 CTA**：导航栏与 Hero 的按钮文案 + 跳转目标根据 `auth.isLoggedIn` 动态切换（"登录" ↔ "进入平台"）
- **首屏无闪烁**：路由守卫 `beforeEach` 调用 `auth.ensureSessionChecked()`，组件挂载前完成 Cookie 会话校验
- **协议页路由复用**：`/terms` 与 `/privacy` 共用 `AgreementView.vue`，通过 `props` 传入类型；Markdown 渲染 + DOMPurify 消毒避免 XSS
- 动态 `document.title` + meta description，组件卸载时还原
- `/:pathMatch(.*)*` 兜底重定向到首页

### 三、发现模块（用户端首页）

平台流量入口，承载活动探索、社区浏览、城市发现、分类订阅四大能力。

#### 前端职责

- **视图层**：`DiscoverView` / `CalendarsDiscoverView` / `CategoryDiscoverView` / `CommunityDetailView` / `EventDetailView`
- **三个 Composable 解耦关注点**：
  - `useDiscoverFilters`（217 行）：筛选状态 ↔ URL Query 双向同步，支持后退/前进恢复
  - `useDiscoverSearch`（174 行）：350ms 防抖 + `AbortController` 取消旧请求
  - `useRecentSearches`：localStorage 搜索历史（最多 10 条，可点击 / 可删除）
- **子组件**：`DiscoverEventCard` / `CommunityCard` / `FilterSummaryBar`（可单项移除筛选标签）/ `SectionHeader`（板块标题 + View All 深链）
- **社区详情页三视图**：列表 / 日历 / 地图视图切换
- **E2E 覆盖**：搜索、路由深链、筛选联动、社区详情、日历分页 6 个 spec 文件，12+ 用例

#### 后端职责

- **多维筛选接口**：`GET /events` 支持 keyword / city / categoryId / dateStart / dateEnd / locationType / sortBy
  - QueryBuilder 动态拼接 + `escapeLike()` 转义 + `ESCAPE '\\'`，杜绝通配符注入
  - **安全默认值**：未传 status 时强制 `status = 'published' AND visibility = 'public'`
  - 三种排序策略：`latest` / `upcoming` / `trending`（门票销量子查询）
- **城市聚合**：`GET /events/cities` 单条 SQL 用 `SUM(CASE WHEN ILIKE :param THEN 1 ELSE 0 END)` 替代 N 次 COUNT
- **活动生命周期事务化**：`publish` / `cancel` / `delete` 在 `dataSource.transaction()` 内原子更新 `Category.eventCount`
- **报名并发安全**（关键改造）：`register` / `cancel` / `approve` / `reject` / `promoteWaitlisted` 全部上 `pessimistic_write` 悲观锁
  - 报名：事务内锁活动行 → 容量检查 → 锁门票行 → 名额检查 → 创建记录 → `soldCount++`
  - 取消 + 候补递补放在**同一事务**内
  - 候补递补用 `Math.min(count, quantity - soldCount)` 计算安全数量
- **权限加固**：`GET /registrations/:id/confirmation` 从公开接口改造为 JWT + 本人 / 创建者权限校验

## 核心设计原则

- **最简原则**：不做冗余设计，仅对必要的多可能事件做冗余
- **安全优先**：安全默认值优于接口校验，不信任客户端输入
- **类型严格**：TypeScript strict mode，前后端均开启 `noImplicitAny`
- **测试驱动**：后端 E2E + 前端 Playwright，改后必测
- **中文注释 / 英文命名**：代码注释、commit message、文档一律中文；变量、函数、类名英文
